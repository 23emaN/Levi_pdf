# การตัดสินใจของผู้ใช้

รายการนี้เรียงตามวันที่ แต่ละข้อบอกสิ่งที่ผู้ใช้ตัดสิน เหตุผลถ้ามีบันทึกไว้ และโค้ดหรือ check ที่ทำตามข้อนั้นในวันนี้
ข้อที่ถูกแทนด้วยข้อใหม่กว่าเขียนว่า "แทนแล้ว" ห้ามถามผู้ใช้ซ้ำในเรื่องที่ตัดสินแล้ว

## กติกาที่ใช้ตลอด

- **ห้ามใช้คำว่า "สกัด"** ในข้อความบนหน้าจอ ผู้ใช้ชาวไทยไม่ใช้คำนี้ ให้ใช้ "ดึงข้อมูล" (แท็บ "1. ดึงข้อมูลจาก PDF")
- **ใช้ "ยอดรวมท้ายบิล" ไม่ใช้คำว่า "footer"** ในข้อความภาษาไทย (check `verify_incremental.py` "no remark, reason or action separates its topics with a middle dot or says "footer"")
- **"สาเหตุ" ต้องบอกปัญหาจริง** ให้ผู้ใช้ตัดสินได้ว่าควรแก้หรือไม่ ไม่เขียนแค่ให้กดปุ่ม (check `verify_incremental.py` "every waiting line of a bill shows one problem and one solution, neither names a button…")
- **หัวคอลัมน์เป็นภาษาอังกฤษ** เช่น `File Name`, `Page` ในตาราง PDF และหัวตาราง ASN และตารางภาพรวม ข้อความอื่นบนหน้าจอเป็นภาษาไทย (check `job_safety_test.php` "the ASN grid has its columns in the new order… every header English", "the dashboard table keeps its exact header texts…")
- **หน้าจอเรียบแบบตาราง Excel** ตารางว่างแสดงแถวเปล่า (`renderPdfEmptyPlaceholderRows` ใน `workspace.php`) วันที่เป็น dd/mm/yyyy (`ui-utils.js`) ปุ่มสร้าง Job เป็นสีเขียว (`.btn-create-job` ใน `app.css`) ไม่มี CSV export และไม่มีปุ่ม copy ในหน้า ASN
- **โค้ดต้องรันบน PHP 7.3** เครื่องจริงของผู้ใช้เป็น PHP 7.3.10 (ชุดทดสอบรันบน PHP 7.3.33 ได้ด้วย `PHP_BIN`)
- **ไม่มี login ของ API** ผู้ใช้ปฏิเสธ
- **ไม่ใช้ git** ไม่มี `.gitignore` และไม่ทำ `.htaccess` เพราะโปรแกรมรันบนเครื่องของผู้ใช้ผ่าน localhost (2026-10-26)

## 2026-10-19 ถึง 2026-10-20

- **ไฟล์ ASN เป็นข้อมูลหลัก** PDF ถูกปรับให้ตรงกับ ASN ไม่มีสถานะ "ไม่มีใน ASN" (`AsnReconciler::reconcile`)
- **การดึงข้อมูลเก็บค่าตามที่พิมพ์ใน PDF** ไม่แก้อัตโนมัติ การแก้เป็นปุ่มที่ผู้ใช้กดเอง (`PdfFixer::fixJob`)
- **ไฟล์ PDF ย้ายจาก `upload here` ไป `finished`** และลบโฟลเดอร์ย่อยที่ว่าง (`api.php` action `extract_job_batch`)
- **นำเข้า ASN แบบสองขั้น** ยืนยันแล้วโหลดเข้าตาราง ปุ่ม "เทียบกับ PDF" แยกต่างหากและมีหน้าต่างยืนยัน อ่านเฉพาะชีตที่มองเห็น ชีตแรกที่มองเห็นเป็นค่าเริ่มต้น (ไฟล์ตัวอย่างมี 19 ชีต ซ่อนอยู่ 11 ชีต เช่น `Issue`, `CDS`, `RBS` ชีตแรกที่มองเห็นคือ `CDS ZFP (ZKE) done 13.10.2026`)
- **เพิ่ม PDF และ ASN ได้หลายรอบ** มีหน้าต่างล้างข้อมูลแบบแบ่งหน้าและเลือกข้ามหน้าได้
- **กติกายอดรวม รุ่นแรก (แทนแล้ว 2026-10-26)** ยอมรับ Cost Ex VAT ของ ASN ถ้าเท่ากับ Amt Excl VAT ท้ายบิล หรือเท่ากับราคาก่อนส่วนลด / 1.07 เพราะ ASN ใส่ราคาก่อนส่วนลดใน 283 จาก 373 บิล ผู้ใช้ให้ยอมรับเงียบ ๆ
- **บิลซ้ำ** ถ้าไฟล์ใหม่มีบิลที่ Job มีอยู่แล้วจากไฟล์ชื่ออื่น ให้เตือนและเลือกข้ามหรือแทนที่ ทั้งฝั่ง PDF และ ASN (`PdfItemStore::scanSourceFiles`, `AsnStore::saveAsnRecords`)

## 2026-10-21

- **หน้าภาพรวมนับเลขบิล ไม่นับแถว** ผู้ใช้ย้ำเรื่องนี้ บิลใช้สถานะที่แย่ที่สุดของรายการ (`DashboardBuilder::getInvoiceDashboard`)
- **"รอแก้ไขทั้งหมด" ต้องไม่ลดลงหลังกดแก้ไข** คือ ยังแก้ไขไม่ได้ + แก้ไขแล้ว บิลที่แก้ไขแล้วแต่ยังผิดนับทั้งสองช่อง และช่องผิดพลาดบอกจำนวน (การ์ดนี้ชื่อ "รอแก้ไข PDF ทั้งหมด" ตั้งแต่ 2026-10-28)
- **การสั่งพิมพ์** บิลที่พร้อมคือบิลสมบูรณ์ที่ยังไม่เคยพิมพ์ สถานะ "พิมพ์แล้ว" ดูจากไฟล์ใน `print/` ลบโฟลเดอร์รอบเพื่อพิมพ์ใหม่ (`PrintManager::printedInvoices`)

## 2026-10-22

- **ปุ่มแก้ไขเขียนแค่ "แก้ไข (N)"** ผู้ใช้ย่อเอง หัวหน้าต่างยืนยันยังเป็น "แก้ไขและแยกไฟล์ PDF" (`workspace.php`)
- **สถานะแสดงผล "แก้ไขแล้ว"** สีน้ำเงิน ไอคอนประแจอย่างเดียว ผู้ใช้ไม่เอาสีเขียวอมฟ้าและเครื่องหมายถูกเพราะใกล้กับสีเขียวของ "สมบูรณ์" (`STATUS_DISPLAY` ใน `state.js`)
- **การแยกไฟล์อย่างเดียวนับเป็นการแก้ไข** "แก้ไขแล้ว" คือทุกบิลที่ปุ่มแก้ไขทำอะไรด้วย (แก้เลข ลบยอดรวม แยกไฟล์ หรือเสียหน้าให้บิลอื่น) (`PdfFixer::recordFixedInvoices`)
- **ตัดสินตั้งแต่ก่อนกดแก้ไข** ผู้ใช้ถามว่าตรวจตั้งแต่แรกไม่ได้หรือ สถานะก่อนกดเท่ากับหลังกด โดยนับรอแก้ไขเป็นสมบูรณ์ (`FixPlan`, `AsnReconciler::reconcile`)
- **บิลที่ต้องแยกไฟล์อย่างเดียวเป็น "รอแก้ไข" ก่อนกดแก้ไข** ผู้ใช้เลือกข้อ "ก" เพราะเห็นรอแก้ไขน้อยก่อนกด แต่แก้ไขแล้วมากหลังกด ผลที่ผู้ใช้ยอมรับคือบิลเหล่านี้พิมพ์ไม่ได้จนกว่าจะกดแก้ไข (`FixPlan::describe`, `FixLog::splitDone`)
- **ไม่มีปุ่มย้อนการแก้ไข** ผู้ใช้ไม่เอา ปุ่มแก้ไขเขียนทับค่าในแถว PDF ล้าง ASN จึงไม่ย้อนการแก้ไข ทางเดียวที่จะเริ่มใหม่คือล้างข้อมูล PDF แล้วดึงข้อมูลใหม่ (ลำดับที่ปลอดภัยอยู่ใน BUSINESS_RULES.md หัวข้อ "เริ่มใหม่ตั้งแต่ต้น") มีการเสนอแบบไม่ทับค่าเดิม (เก็บค่าดิบและการแบ่งหน้าแยกกัน) แต่ผู้ใช้ไม่เลือก ให้กลับมาคุยถ้าผู้ใช้เปลี่ยนไฟล์ ASN หลังแก้ไขบ่อย
- **Remark คอลัมน์เดียว** รวม Discrepancy กับ Action ป้าย `ปัญหา : ` และ `วิธีแก้ไข : ` บิลสมบูรณ์เขียน `ข้อมูลถูกต้อง` บิลแก้ไขแล้วแสดงบันทึกการแก้ไขไม่มีป้าย (`REMARK_LABELS`, `reconRemark` ใน `state.js`)
- **คั่นหัวข้อด้วยจุลภาค** ผู้ใช้ไม่เอาจุดกลาง (·) หน้าในหัวข้อเดียวกันใช้ "และ" ไม่มีคำนำหน้า "แก้ไขแล้ว:" และไม่ใส่ชื่อไฟล์ในหมายเหตุ (`FixLog::TOPICS`, `FixLog::pagesText`)
- **ชื่อไฟล์ต้องอ่านได้ครบ** ไม่ตัดด้วย "…" ผู้ใช้บ่นสองครั้ง เพิ่มคอลัมน์ `Source File`
- **คำว่า "สั่งพิมพ์"** หัวคอลัมน์ในหน้า ASN คือ `Print` ชื่อโฟลเดอร์ `print` และ `print ครั้งที่ N` คงเดิม โฟลเดอร์ในรอบตั้งตาม Dest Store No. ไฟล์ชื่อ `1_x.pdf` ไม่เติมศูนย์ (`PrintManager::finish`)
- **ตารางภาพรวมมีตัวกรอง ช่องค้นหา และ Excel** ผู้ใช้ขอเอง กลับคำตัดสินเดิมที่ไม่เอา
- **เปิดโฟลเดอร์ต้องบอกผล** ถ้าเปิด Explorer ไม่ได้ แสดงหน้าต่างที่มี path และปุ่มคัดลอก (`FileManager::openInExplorer`)
- **เปิดโฟลเดอร์ได้แม้ Apache เป็น Windows service** เครื่องที่ใช้ AppServ รัน Apache เป็น service ซึ่งไม่มีหน้าจอของผู้ใช้ `FileManager::explorerCommand` จึงส่งสคริปต์เดิมไปรันเป็น scheduled task ชั่วคราวของกลุ่ม Users ใน session ของผู้ใช้ที่ login อยู่ แล้วลบ task ทิ้ง ผลยังมาจากการตรวจหน้าต่างจริงเหมือนเดิม ถ้าทำไม่ได้ยังแสดงหน้าต่าง path และปุ่มคัดลอก

## 2026-10-26

- **กติกายอดรวมแบบเข้ม** บิลผิดพลาดเมื่อ Amt Excl VAT ของ PDF กับ Cost Ex VAT ของ ASN ต่างกันเกิน 1.00 บาท เลิกยอมรับราคาก่อนส่วนลด / 1.07 ผู้ใช้รู้ก่อนตัดสินว่าบิลส่วนใหญ่จะกลายเป็นผิดพลาด (`AsnReconciler::AMOUNT_TOLERANCE`, check `job_safety_test.php` "ASN cost equal to the list price / 1.07 but not to the PDF footer is wrong now…")
- **ข้อความยอดรวมบอกสองค่าเท่านั้น** `ยอดรวมไม่ตรง (PDF: x / ASN: y)` ไม่บอกเกินหรือขาด ไม่บอกผลต่าง ไม่มี ฿ ในประโยคนี้ ส่วน VAT ยังมี ฿ (`AsnReconciler::amountProblem`)
- **บิลผิดพลาดแสดงปัญหาอย่างเดียว** บรรทัดเดียว `ปัญหา : …` สีแดง ไม่มีวิธีแก้ไข ผู้ใช้ตรวจที่ต้นทางเอง
- **ตรวจบาร์โค้ดที่มีแต่ใน PDF** ทำให้ทั้งบิลผิดพลาดแม้ยอดรวมต่างไม่เกิน 1.00 บาท (`AsnReconciler::PDF_ONLY`)
- **ตรวจยอดรวมท้ายบิลกับรายการของบิลเอง** ผู้ใช้บอกว่ายอดรวมท้ายบิลอาจสลับกันระหว่างบิลในไฟล์เดียว (`AsnReconciler::footerProblems`)
- **ไม่ตรวจราคาต่อชิ้นและไม่แยกเกินหรือขาดรายบาร์โค้ด** ผู้ใช้ไม่เอา และข้อมูลแสดงว่าทำไม่ได้: ราคาใน ASN เท่ากับราคาใน PDF (ทุกแบบของส่วนลดและ /1.07) 0 จาก 1,724 รายการ ASN ไม่มียอดเงินรายแถว และผลรวมราคา ASN × จำนวน เท่ากับยอดรวม PDF แค่ 40% ของบิล
- **ลบ Job ต้องพิมพ์ชื่อ Job** มีนับถอยหลัง 3 วินาที และแสดงสรุปสิ่งที่จะหายก่อน API ตรวจชื่ออีกครั้ง (`api.php` action `delete_job`, `DELETE_JOB_WAIT_MS` ใน `index.js`)
- **แถบสถานะ** `PDF: N ไฟล์ | รายการ: N รายการ | ASN: N ไฟล์ | รายการ: N รายการ` ไม่มียอดเงินรวม (`JobManager::statusCounts`)
- **ตาราง ASN ตรึงสามคอลัมน์แรก** `#`, `Status`, `Tax Invoice No.` ผู้ใช้ย้ายจุดตรึงจาก `Print` มาที่ `Tax Invoice No.` (`ASN_COLUMNS` ใน `workspace.php`)

- **คลิกขวาที่หัวคอลัมน์เพื่อระบายสีทั้งคอลัมน์** ใช้ได้ทั้งสามตาราง (PDF, ASN, ภาพรวม) เมนูมีสีพาสเทล 8 สี สีอื่น ไม่มีสี และล้างสีทั้งตาราง ผู้ใช้ขอแบบ Excel หัวคอลัมน์ระบายสีเดียวกับคอลัมน์ (ขอบล่างเข้มขึ้นเล็กน้อยให้ยังอ่านเป็นหัวตาราง) และถ้าเลือกสีเข้มตัวอักษรของหัวและเซลล์เป็นสีขาว สีเก็บในเบราว์เซอร์ของเครื่องที่ใช้ แยกตาม Job ไม่เข้าฐานข้อมูล และยังไม่ใส่สีในไฟล์ Excel เพราะ SheetJS รุ่นฟรี 0.18.5 ที่ใช้อยู่เขียนสีเซลล์ไม่ได้ (`assets/js/workspace/column-highlight.js`, `tests/column_highlight.js`)
